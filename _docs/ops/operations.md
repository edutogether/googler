# 실운영 상태 — 그냥 돌리면 된다

2026-10-10 종합감사 10/10 뒤 정리한 운영 안내다. 이 앱은 전시용 정적 셸이라 서버·데이터베이스를 직접 돌리지 않는다.

## 자동으로 도는 것

- **배포**: `main`에 푸시하면 검사(typecheck·lint·테스트·규칙 테스트·빌드) → Firebase Hosting 배포 → Firestore 규칙 배포가 순서대로 돈다. 배포는 한 번에 하나씩 순서대로 돈다(`concurrency`). 규칙 배포가 실패해도 Hosting 배포는 이미 끝나 있고, 실패 경고 단계가 Actions 화면에 표시를 남긴다.
- **문서만 바뀐 커밋**은 배포하지 않고 검사만 돈다.
- **PR 미리보기**: `main`을 향한 PR이면 임시 주소가 PR에 달린다. Dependabot PR은 미리보기를 건너뛴다.
- **보안**: Dependabot 보안 업데이트(보안 수정 PR만 열린다), CodeQL(푸시마다·주기적으로), 비밀 스캔과 푸시 차단이 켜져 있다.
- **오류 수집**: 배포된 화면의 오류를 Sentry가 받는다. 개인정보는 보내지 않고 하루 20건 상한이 있다.
- **백업**: 운영 데이터가 없다(라이브는 Firebase를 호출하지 않는다). 코드는 GitHub에 있고, 되돌릴 지점은 프리즈 태그다(`freeze-recovery.md`).
- **알림**: Google Cloud 예산 알림은 임계값을 넘으면 메일만 온다(호출을 막지는 않는다).

## 사람이 주기적으로 할 일

- 없음. Dependabot 보안 PR이 열리면 검사가 초록인지 보고 병합하면 된다(병합 = 배포).
- 분기 말(3·6·9·12월 마지막 날) 정기 종합감사. 다음은 2026-12-31. 사소한 수정이 쌓였을 때 먼저 돌려도 된다.

## 문제가 생기면 어디부터 보나

1. 화면이 안 열리거나 이상하다 → GitHub Actions의 마지막 `Deploy to Firebase Hosting on merge` 실행이 초록인지.
2. 초록인데 이상하다 → `node D:/Projects/_shared/ops/smoke-check.mjs _docs/ops/smoke.json`(첫 화면 문구 확인).
3. 되돌려야 한다 → `freeze-recovery.md`의 절차(최신 프리즈 태그로 복원 후 푸시).
4. 오류가 쌓인다 → Sentry. 일일 상한 때문에 하루 20건까지만 온다.
